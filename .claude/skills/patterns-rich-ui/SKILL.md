## 樣式 1:拍照 OCR 自動填表（Google Vision API）

**何時用**:任何「現場有張紙(名片 / 收據 / 保單 / 證件),想拍一張就自動填欄位」的需求。

**為什麼用 Vision 不用 Tesseract**:準度高很多(尤其繁中)、不用裝 npm 套件(純 `fetch` + API key)、免費額度 1000 次/月夠家用。

**金鑰**:`web/.env.local` 放 `GOOGLE_VISION_API_KEY=...`(server-only,**不加** `NEXT_PUBLIC_`)。GCP 建金鑰時:API 限制只勾 Cloud Vision API;應用程式限制設「無」(server 端呼叫沒 referrer,設網站限制會壞);**不要**勾「透過服務帳戶驗證」(那是 Vertex/Gemini 用)。改 `.env.local` 後要重啟一次 dev server。

**Route 骨架**(`POST /api/vision-ocr`,收 multipart 一張圖):
```ts
const res = await fetch(`https://vision.googleapis.com/v1/images:annotate?key=${apiKey}`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    requests: [{
      image: { content: base64 },                  // Buffer.from(await file.arrayBuffer()).toString("base64")
      features: [{ type: "TEXT_DETECTION" }],
      imageContext: { languageHints: ["zh-Hant", "en"] },
    }],
  }),
});
const rawText = data?.responses?.[0]?.fullTextAnnotation?.text ?? "";
```

**關鍵心法:OCR 只負責出「整段文字」,解析欄位是另一回事**。route 內把 `rawText` 切行後用 regex / 啟發法抽欄位回傳結構化 JSON,前端拿到直接填。家電名片範例抽了:店家名稱、聯絡人、市話、行動、地址、濃縮備註。

**台灣電話格式**(踩過坑,直接抄):
- 行動:`/09\d{2}[-\s.]?\d{3}[-\s.]?\d{3}/` → 格式化 `09NN-NNN-NNN`
- 市話:`/\(?0(89|37|39|49|2|3|4|5|6|7|8)\)?[-\s.]*(\d{3,4})[-\s.]*(\d{3,4})/` → **長區碼放前面**(否則 `0`+`3` 會先吃掉 037);格式化 `02-NNNN-NNNN` / `037-NNN-NNNN`
- 全形數字先轉半形:`s.replace(/[０-９]/g, d => String.fromCharCode(d.charCodeAt(0) - 0xfee0))`

**前端填表心法:空欄才填,不蓋掉使用者已打的**:
```ts
setForm(f => ({ ...f, name: f.name || data.name || "", phone: f.phone || data.phone || "" /* ... */ }));
```

**相機輸入**:`<input type="file" accept="image/*" capture="environment">`(手機開後鏡頭,桌機開檔案選擇器)。

**老實話(自己標出的簡化)**:聯絡人靠「職稱關鍵字旁的 2~4 中文字」、備註靠「沒被其他欄位用到的中文行」,排版怪會抓空 / 抓雜訊 → 一定要讓使用者能手動修。

## 樣式 2:多檔上傳區（強制標準，見 CLAUDE.md「上傳區標準」）

**何時用**:任何 Drive 上傳區。**這是強制標準**,所有板塊一致,不要每個板塊各做一套。

**三鐵則**:① 縮圖列表可多檔、② 選檔複選 + Ctrl+V 貼上、③ 外觀統一套 `MultiUpload`。

**資料模型:獨立子表 `<module>_files`**(不要再用 `photo_url` / `manual_url` 單欄存單檔的舊做法):
```sql
create table if not exists <module>_files (
  id           bigint generated by default as identity primary key,
  <parent>_id  bigint not null references <parents>(id) on delete cascade,
  kind         text not null,          -- 'photo' | 'manual' | 'receipt' ... 一個上傳區一個 kind
  url          text not null,          -- Drive view URL
  name         text,                   -- 原始檔名(顯示 / 判斷副檔名)
  created_at   timestamptz not null default now()
);
create index if not exists idx_<module>_files_parent on <module>_files(<parent>_id);
```

**領域檔** `lib/<module>Files.ts`:只管 DB(`listFiles(parentId?)` / `getFile` / `createFile` / `deleteFile`),**Drive 上傳/刪除在 route 做**(lib 不碰 Drive,維持 server 分層乾淨)。

**API**:
- `POST /api/<module>-files`(multipart:`parent_id` + `kind` + `file`)→ 先 `uploadFile()` 上 Drive →`createFile()` 寫 DB → 回新列
- `DELETE /api/<module>-files/[id]` → 先 `deleteFileByUrl()` 刪 Drive 實體檔 → 刪 DB 列
- `GET /api/<module>-files?parent_id=N`(列表,主頁載入用)
- Drive 命名沿用 `<主物件名>-<kindLabel>-<原檔名>`;kindLabel 寫死 map(`photo→家電照片` 等),**做新板塊前主動列 2-3 個 kindLabel 候選讓 Kevin 挑**

**前端**:
- `loadXxx()` 平行多 fetch 一個 `API_FILES`,用 `filesByParent[id]` 分組;再 `filesOf(id, kind)` 取某區檔案
- 一個 `MultiUpload` 元件,三個上傳區各放一個(props:`label` / `accept` / `files` / `uploading` / `onActivate` / `onUpload` / `onDelete`)
- **Ctrl+V 路由**:用一個 `activeUploadKind` state,每個 `MultiUpload` 的 `onMouseEnter` / `onFocusCapture` 設定它;document 層 `paste` 事件把貼上的圖丟給 `activeUploadKind` 那區(可一次貼多張)
- `<input type="file" multiple>`;`onChange` 後 `e.target.value = ""` 才能連選同名檔
- 縮圖:圖片用 `https://drive.google.com/thumbnail?id=${fileId}&sz=w160`(`fileId` 從 view URL regex 反解),PDF(看檔名 `.pdf`)顯示 📄;`onError` 時 `display:none`
- 主物件 `deleteAppliance` 要先 `listFiles(id)` 把 Drive 檔逐一刪掉(cascade 只刪 DB 列、不刪 Drive 實體檔!)

**踩過的坑**:cascade **不會**清 Drive 的實體檔,刪主物件 / 刪單檔都要自己呼叫 `deleteFileByUrl`。

## 樣式 3:分類別子表（一主物件掛多筆，各帶 category）

**何時用**:一個主物件下有「多筆同類資訊,但每筆可能是不同小類,欄位也略不同」。家電聯絡資訊範例:類別 = 耗材連結 / 保養資訊 / 購買店家,耗材連結填「名稱 + 連結」,後兩者填「店家 + 聯絡人 + 電話 + 地址」。

**跟樣式 2 的差別**:這是**結構化文字**多筆(存 Supabase),不是檔案。

**資料模型**:一張子表,一個 `category text` 欄位,所有類別共用一張表(欄位取聯集,某類別用不到的欄位就留 null):
```sql
create table if not exists <module>_contacts (
  id bigint generated by default as identity primary key,
  <parent>_id bigint not null references <parents>(id) on delete cascade,
  category text not null,        -- 類別合法值在領域檔用 const 陣列定義
  name text, contact_person text, url text, phone text, mobile text, address text, note text,
  also_maintenance boolean default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

**領域檔**:`export const CONTACT_CATEGORIES = [...] as const;` + `type Category = typeof[number]`(前端下拉直接用,型別也鎖);CRUD 同單表模板;`Update = Partial<Omit<Create, "<parent>_id">>`(子物件不能換父)。

**前端**:表單最上面一個「類別」select,下方欄位**用 `category` 條件 render**(`{form.category === "耗材連結" ? <連結欄位/> : <店家欄位/>}`);送出時依類別把不相干欄位送 null。列表用一個 `Row` 元件,類別用色票徽章區分。

**心法**:不要為每個類別開一張表 —— 共用一張 + category 欄位最省,欄位聯集即可。

## 樣式 4:動態篩選列（chips 選項由資料長出來、多排疊加）

**何時用**:想依某個欄位值篩選列表,而**值是使用者自己填的、不固定**(區域 / 標籤 / 分類…)。

**作法**:選項不要寫死,從現有資料 distinct 出來:
```ts
const locationOptions = Array.from(
  new Set(items.map(a => (a.location ?? "").trim()).filter(l => l !== "")),
);
```
新增資料填了新值,chip 自動多一顆,零維護。

**多排疊加**:每排一個獨立 state(`filter` 狀態排 + `locationFilter` 區域排),篩選時依序套用(`filtered = filtered.filter(...)`),效果是 AND 疊加。

**視覺分類**(Kevin 要求):不同類別的篩選排要看得出是兩類 —— 用**分隔線**(`border-t`)+ 排首一個淺灰小標籤(「區域」)+ **不同選中色**(狀態排黑底、區域排藍底)區隔。選項多時該排 `overflow-x-auto` 可橫滑、chip 加 `whitespace-nowrap`。

**小坑**:全部資料該欄位都空時,整排別 render(`{options.length > 0 && ...}`),免得留空排。

## 通用工作流程提醒（這輪驗證有效的)

1. **DDL 直接用 `supabase_admin.py` 跑**,絕對路徑呼叫(PowerShell 工作目錄會殘留):
   `& "C:\...\venv\Scripts\python.exe" "C:\...\supabase_admin.py" "ALTER TABLE ..."`,輸出 `(no rows)` = 成功。`ADD/DROP COLUMN` / `CREATE TABLE/INDEX` 直接跑不用問。
2. **換資料模型要搬舊資料再 drop 舊欄位**:`INSERT INTO 新表 SELECT ... FROM 舊表 WHERE 非空` → 再 `ALTER TABLE DROP COLUMN`,別直接 drop 掉資料。
3. **每改完自己跑** `cd web && npx tsc --noEmit`,型別錯自己修,別丟 Kevin。
4. **route.ts / page.tsx 改動靠 hot-reload**,不用重啟;**只有改 `.env.local` / 裝套件 / server 掛了**才重啟一次。
5. **Kevin 只驗兩件事**:網頁是否如預期顯示 + 文字資料是否進 Supabase。中間 SQL / 程式碼不用先給他看點頭。
6. **不啦啦隊**:自己做的簡化(OCR 抓不準、頭貼用第一張、kindLabel 拍板…)主動標出讓他反對。
